# draft-pr

プルリクエストは **Draft で作成するのがデフォルト**。Ready 状態の PR はレビュアーに通知が飛び、レビュー依頼として扱われる。ユーザーが自分で中身を確認してから Ready にできるよう、明示的な指示がない限り Draft で出す。

## 判定ルール

PR を作成する前に、ユーザーの指示を確認して作成モードを決める。

| ユーザーの指示 | 作成モード |
|---|---|
| 特に指定なし（「PR作って」など） | **Draft** |
| 「Draftで」「下書きで」 | **Draft** |
| 「Draftじゃなくていい」「Draftにしないで」「通常のPRで」 | Ready |
| 「Ready for review で」「レディーフォーレビューにして」「レビュー可能な状態で」「すぐレビューに出して」 | Ready |

- 判断に迷う曖昧な表現（「ちゃんとしたPRで」「正式に出して」など）は Draft で作成し、Ready に変更できることを一言添える。推測で Ready にしない。
- Ready の指示は **その PR 1件に対してのみ** 有効。以前の会話で Ready を指示されていても、新しい PR では改めて Draft をデフォルトにする。

## 作成手順

### Draft で作成する場合（デフォルト）

```bash
gh pr create --draft --title "<タイトル>" --body "<本文>"
```

- `--draft` フラグを必ず付ける。付け忘れは後から戻せない通知を発生させるため、コマンドを実行する前にフラグを確認する。
- GitHub MCP などの API 経由で作る場合も `draft: true` を指定する。

### Ready で作成する場合（明示的な指示があったときのみ）

```bash
gh pr create --title "<タイトル>" --body "<本文>"
```

## 作成後の報告

- PR の URL と、**Draft / Ready のどちらで作成したか** を必ず伝える。
- Draft で作成した場合は、Ready にするコマンドを添える:

```bash
gh pr ready <PR番号>
```

## 既存の Draft PR を Ready にしてほしいと言われた場合

新規作成ではなく、既存 PR の状態変更として `gh pr ready <PR番号>` を実行する。
